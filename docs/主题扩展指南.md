# signal-insight 可视化主题扩展指南

本文说明如何为 `signal_insight` 新增或修改可视化主题。阅读完后，你应该能在不改动任何 Python 代码的前提下，交付一套符合企业规范的新配色。

相关文档：只是**使用**现有主题，看《主题使用说明》；图表本身的要求（结构、配色纪律、字体合规、审图清单）以《图表规范》为准，新主题不得与它冲突。

---

## 1. 快速开始

最常见的需求是"在已有主题的基础上换一套颜色"。只需要两步。

**第一步**：在项目根目录（含 `signal.workspace` 的那一层）的 `themes/` 文件夹里新建一个 TOML 文件，例如 `themes/acme.toml`：

```toml
name = "acme"
base = "business"
description = "ACME 品牌配色"

main = "#E60012"
categorical = ["#E60012", "#1F2937", "#F59E0B", "#10B981", "#3B82F6", "#8B5CF6"]
```

**第二步**：在出图代码里应用它：

```python
from signal_insight import viz
viz.apply_theme("acme")
```

`viz` 被导入时会自动扫描 `themes/` 目录并注册所有主题，没写的字段一律继承自 `base`。

---

## 2. 整体结构

主题系统分为三层，各管一件事：

| 文件 | 职责 | 新增主题时是否需要改 |
|---|---|---|
| `src/signal_insight/theme.py` | 定义 `Theme` 数据结构、内置主题、注册表、TOML 加载 | 一般不需要 |
| `../src/signal_insight/viz.py` | 业务语义映射（哪个区域/客群用哪个颜色角色）、`apply_theme`、`finish` | 只有新增区域或客群时需要 |
| `src/signal_insight/config.py` | 默认主题名 `THEME`、自定义主题目录 `THEME_DIR` | 只有更换默认主题时需要 |
| `themes/*.toml` | 自定义主题 | **新增主题就是在这里加文件** |

关键的设计原则是：**业务代码只引用"颜色角色"，不写死色值**。例如"西塔"永远使用第 0 个分类色，"过夜地不明"永远使用 `gray`。具体是什么颜色由当前主题决定，所以切换主题后，"同一区域在所有图里同色""不明永远是灰色"这类规则依然成立。

### 当前已有的主题

| 名称 | 来源 | 风格 |
|---|---|---|
| `default` | 内置 | 项目原配色：灰色打底、蓝色强调、红色只表示警示 |
| `academic` | 内置 | 学术规范：Okabe-Ito 色盲友好色板，衬线字体，四面边框，内向刻度，无网格 |
| `business` | 内置 | 商业规范：明快的品牌色板，无衬线字体，线条更粗 |
| `lively` | `themes/lively.toml` | 课件"活泼"配色：蓝色主调、粉色点睛、分区上色 |

查看当前已注册的全部主题：

```python
from signal_insight import viz
print(viz.available_themes())
```

## 3. 配色纪律（所有主题都必须遵守）

新主题可以改变色相、明度和字体，但下面四条规则不能破坏。它们决定了图表在不同主题之间语义一致。

1. **灰色打底。** 背景数据、次要数据、"不明"类别使用 `gray` / `gray_dark`。灰色不能出现在 `categorical` 里，否则读者会把某个区域误认为"不明"。
2. **一种颜色只表达一件事。** `main` 用于强调这张图要说的那件事，不要同时用它表达别的含义。
3. **红色只表示警示。** `alert` 专用于警示。`categorical` 里不要放和 `alert` 相近的红色。如果品牌主色本身就是红色，就把 `alert` 换成另一个醒目且与主色区分得开的颜色（例如深棕红或黑色），并在团队内统一说明。
4. **`categorical[0]` 建议等于 `main`。** 这样单系列图和多系列图的主色保持一致。
5. **只用开源字体。** 这是《图表规范》第 0 节的合规红线。主题里写商业字体会直接报错，详见 4.5 节。
6. **连续数值用单色渐变。** 不用彩虹色阶，`sequential` 必须是主色由浅到深的单色渐变。

## 4. `Theme` 字段完整参考

TOML 文件中的键与下表字段名一一对应。除 `name` 外都可以省略，省略时继承 `base`。

### 4.1 元信息

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | 字符串 | **必填**。主题名，`apply_theme("名字")` 用的就是它 |
| `base` | 字符串 | 仅 TOML 可用。继承的主题名，默认 `"default"` |
| `description` | 字符串 | 一句话说明用途，便于团队挑选 |

### 4.2 语义色

所有颜色必须写成 `#RRGGBB` 或 `#RRGGBBAA`，不支持 `"blue"`、`rgb()` 等写法。

| 字段 | 用途 | 对应的旧常量 |
|---|---|---|
| `main` | 主色，强调核心信息；也是 `finish()` 标题色条的颜色 | `MAIN` |
| `main_dark` | 主色的深色版，用于强调中的强调、色图深端 | `MAIN_DARK` |
| `main_mid` | 主色的中间调，用于同色系第二层级 | `MAIN_MID` |
| `main_light` | 主色的浅底，用于高亮区间、背景块 | `MAIN_LIGHT` |
| `gray` | 打底色、"不明"类别 | `GRAY` |
| `gray_dark` | 深一级的灰 | `GRAY_DARK` |
| `alert` | **只用于警示** | `RED` |
| `warn` | 次级提醒、警告 | `AMBER` |
| `ok` | 通过（状态色：通过绿 / 警告黄 / 不通过红） | `GREEN` |
| `ink` | 标题、坐标轴标签文字 | `INK` |
| `muted` | 副标题 | `MUTED` |
| `faint` | 来源行 | `FAINT` |

### 4.3 画布

| 字段 | 用途 |
|---|---|
| `background` | 图与坐标区的背景色，也用于保存图片时的底色 |
| `grid` | 网格线颜色 |
| `edge` | 坐标轴线颜色 |
| `tick` | 刻度及刻度文字颜色 |

### 4.4 色板与色图

| 字段 | 类型 | 说明 |
|---|---|---|
| `categorical` | 颜色列表 | 分类色。会成为 matplotlib 默认的颜色循环，区域按顺序依次取色。**建议至少 6 个**，因为目前有 6 个区域；不足时会循环复用，相同颜色会让两个区域无法区分 |
| `sequential` | 颜色列表 **或** 色图名 | 连续色图，列表按"浅 → 深"排列，至少 2 个颜色。按《图表规范》应为主色的**单色渐变**；技术上也可以写 matplotlib 色图名（如 `"Blues"`），但不要用 `jet`、`rainbow` 等彩虹色阶 |
| `diverging` | 颜色列表 **或** 色图名 | 发散色图，列表按"负 → 中 → 正"排列，中间色建议接近背景色 |

颜色列表形式的色图会自动注册为 `"<主题名>.sequential"` 和 `"<主题名>.diverging"`，`sequential` 同时设为 `imshow` 等函数的默认色图。

### 4.5 字体与标题区

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `fonts` | 字符串列表 | `["TeX Gyre Termes", "Noto Serif CJK SC"]` | 字体优先级列表。前面的放西文字体，后面的放中文字体。**只能写开源字体**，规则见下文 |
| `title_size` | 数字 | `16` | `finish()` 标题字号 |
| `subtitle_size` | 数字 | `10.5` | 副标题字号 |
| `source_size` | 数字 | `8.5` | 来源行字号 |
| `accent_bar` | 布尔 | `true` | 是否在标题上方画主色小色条；学术主题设为 `false` |

《图表规范》规定标题 16、副标题 10.5、来源行 8.5；新主题如需偏离（例如学术主题的 13 / 10 / 8），要在规范第 3 节中登记理由。

**字体的处理规则**（由 `theme.resolve_fonts` 自动完成，写主题时只需了解）：

1. **思源字体只写一个名字就够。** 同一套字形有多个发行名，写任一个都会自动展开成整组：
   - 黑体：Source Han Sans SC / Noto Sans CJK SC / Noto Sans SC / Noto Sans CJK JP / WenQuanYi Zen Hei
   - 宋体：Source Han Serif SC / Noto Serif CJK SC / Noto Serif SC / Noto Serif CJK JP
2. **自动补回退链。** 主题字体之后会补上开源黑体链（衬线中文缺失时退到黑体，而不是方框），只保留本机已安装的，最后加 DejaVu Sans 兜底负号和上下标。
3. **商业字体直接报错。** 微软雅黑、黑体、宋体、楷体、苹方、Hiragino、Times New Roman、Arial、Helvetica、Calibri 等写进 `fonts` 都会在加载主题时抛出 `ValueError`。需要类似效果时，用开源替代品：

| 想要的效果 | 用这个开源字体 |
|---|---|
| 黑体 / 微软雅黑 / 苹方 | Source Han Sans SC（写 `Noto Sans CJK SC` 也一样） |
| 宋体 | Source Han Serif SC（写 `Noto Serif CJK SC` 也一样） |
| Times New Roman | TeX Gyre Termes |
| Helvetica / Arial | TeX Gyre Heros |

### 4.6 `rc`：matplotlib 参数补丁

`rc` 是一个表，里面的键值会在最后直接写进 `matplotlib.rcParams`，用来表达主题的"手感"差异。在 TOML 中，带点号的键必须加引号：

```toml
[rc]
"lines.linewidth" = 2.2
"axes.spines.left" = true
"xtick.direction" = "in"
```

派生主题时，`rc` 是**合并**而不是整体替换：子主题只需写要改动的键，其余沿用 `base` 的 `rc`。

所有主题共用的基础参数如下，可以在 `rc` 中覆盖其中任何一项：

| 参数 | 默认 | 含义 |
|---|---|---|
| `axes.spines.top` / `right` / `left` | `false` | 只保留底部轴线 |
| `axes.grid` / `axes.grid.axis` | `true` / `"y"` | 只画水平网格 |
| `xtick.major.size` / `ytick.major.size` | `0` | 不画刻度线 |
| `legend.frameon` | `false` | 图例无边框 |
| `figure.dpi` / `savefig.dpi` | `100` / `300` | 屏幕与保存分辨率 |

常用的风格开关：

| 想要的效果 | `rc` 写法 |
|---|---|
| 四面边框（论文风） | `"axes.spines.top" = true`，`"axes.spines.right" = true`，`"axes.spines.left" = true` |
| 刻度朝内 | `"xtick.direction" = "in"`，`"ytick.direction" = "in"`，并把刻度长度设为 3.5 左右 |
| 关闭网格 | `"axes.grid" = false` |
| 线条更粗、圆头 | `"lines.linewidth" = 2.2`，`"lines.solid_capstyle" = "round"` |
| 公式字体与 Times 一致 | `"mathtext.fontset" = "stix"` |
| 子图标题加粗 | `"axes.titleweight" = "bold"` |

> **注意**：不要设置 `"patch.linewidth" = 0`。它会让 `annotate` 的箭头消失，因为箭头本身也是 patch。

## 5. 三种扩展方式

### 方式一：TOML 文件（推荐）

适用于绝大多数情况，不需要改代码，非开发人员也能维护。

1. 在 `themes/` 下新建 `<主题名>.toml`，文件名与 `name` 保持一致，方便查找。
2. 写上 `name`、`base`，以及与 `base` 不同的字段。
3. 重新导入 `viz`（Jupyter 中需要重启内核），然后调用 `apply_theme("<主题名>")`。

完整示例（即现有的 `themes/lively.toml`）：

```toml
name = "lively"
base = "business"
description = "活泼：课件配色，蓝色主调、粉色点睛、分区上色"

main = "#3E8EDE"
main_dark = "#1F5FA6"
main_mid = "#8DBCEB"
main_light = "#EEF5FD"
gray = "#C9D3E1"
gray_dark = "#8591A7"
alert = "#D9534F"
warn = "#C06A22"
ok = "#23806F"
ink = "#2A3550"
muted = "#55617A"
faint = "#8591A7"

background = "#FFFFFF"
grid = "#E2E8F1"
edge = "#B9C3D3"
tick = "#55617A"

categorical = ["#3E8EDE", "#E66A8D", "#3DB29F", "#C06A22", "#5A4BB8", "#23806F"]
sequential = ["#F7FAFE", "#D6E7F9", "#8DBCEB", "#3E8EDE", "#1F5FA6"]
diverging = ["#E66A8D", "#F5C0CF", "#F4F6FA", "#8DBCEB", "#1F5FA6"]

# 字体：未写则继承 business（TeX Gyre Termes + 思源宋体）

[rc]
"lines.linewidth" = 1.8
"lines.solid_capstyle" = "round"
"lines.solid_joinstyle" = "round"
```

**关于继承链。** TOML 文件之间也可以互相继承，但 `themes/` 目录按**文件名字母顺序**加载，被继承的主题必须先加载。例如 `acme_print.toml` 写了 `base = "acme"`，那么 `acme.toml` 的文件名需要排在它前面（`acme.toml` < `acme_print.toml`，满足条件）。如果顺序不满足，可以给文件名加数字前缀，如 `10_acme.toml`、`20_acme_print.toml`。

### 方式二：代码中派生

适合在 notebook 里临时试色，或者主题需要由程序计算生成的情况。

```python
from signal_insight import viz
from signal_insight.theme import get_theme, register_theme

acme = get_theme("business").derive(
    "acme",
    main="#E60012",
    categorical=("#E60012", "#1F2937", "#F59E0B", "#10B981", "#3B82F6", "#8B5CF6"),
    rc={"lines.linewidth": 2.4},   # 与 business 的 rc 合并
)
register_theme(acme)
viz.apply_theme("acme")
```

也可以不注册，直接传入对象：`viz.apply_theme(acme)`。

### 方式三：完整构造 `Theme`

只在需要定义一套与现有主题完全无关的风格，并打算把它加入内置主题时使用。做法是在 `theme.py` 中仿照 `ACADEMIC` / `BUSINESS` 写一个常量，并加入文件中的注册循环：

```python
for _t in (DEFAULT, ACADEMIC, BUSINESS, YOUR_THEME):
    register_theme(_t)
```

加入内置主题意味着所有使用者都会看到它，请与团队确认后再提交。

## 6. 覆盖内置主题

企业的视觉规范更新后，可能想直接修改 `business` 的颜色，又不希望改动业务代码里的 `apply_theme("business")`。做法是在 `themes/` 下放一个 `name = "business"` 的文件：

```toml
name = "business"
base = "business"      # 以内置 business 为底，只改需要改的
main = "#0052D9"
```

`themes/` 目录中的同名主题会覆盖内置主题。在代码中用 `register_theme` 覆盖时，必须显式传入 `overwrite=True`，以防误操作。

## 7. 使用主题

```python
from signal_insight import viz, config

# 全局应用：不传参数则使用 config.THEME
viz.apply_theme("business")

# 临时切换：退出 with 后 rcParams 和模块常量都会恢复
with viz.use_theme("academic") as t:
    fig, ax = plt.subplots()
    ax.plot(x, y, color=t.main)
    ax.axhline(limit, color=t.alert)
    viz.finish(fig, "标题", "副标题", config.SOURCE_NOTE, "paper/fig1.pdf")

# 取颜色的推荐写法
t = viz.current_theme()
t.main               # 语义色
t.color(2)           # 第 2 个分类色（超出长度会循环）
t.resolve("cat:3")   # 按角色名取色，与 AREA_ROLE / SEG_ROLE 写法相同
t.cmap("diverging")  # 返回 Colormap 对象
viz.AREA_COLOR["西塔"]  # 业务语义色
```

### 切换默认主题

修改 `config.py` 中的 `THEME`，或者在运行时设置环境变量，环境变量优先：

```bash
SIGNAL_THEME=academic python run.py
```

### 关于 `from viz import MAIN`

`from signal_insight.viz import MAIN` 和 `viz.MAIN` 两种写法都会跟着主题变：切换主题时，`viz._rebind_imported` 会扫描已加载的模块和当前调用栈的全局命名空间，把名字相同、且正是上次导出的那个对象的常量换成新值。改名导入（`as`）、函数默认参数、局部拷贝不会被重绑，详见《主题使用说明》第 4 节。

新增颜色常量时，记得同时加进 `viz._LEGACY` 和 `__all__`，它才会参与重绑和 `import *`。

## 8. 新增区域或客群

这是唯一需要修改 `viz.py` 的情况，而且与主题无关。所有主题会自动生效。

```python
# viz.py
AREAS = ("西塔", "太原街商圈", "中街商圈", "沈阳北站", "沈阳世博园", "棋盘山风景区", "新区域")

SEG_ROLE = {
    "市内来访": "main", "周边居民": "main_mid",
    "外地来客": "cat:1", "市外来访": "cat:1",
    "过夜地不明": "gray",
    "新客群": "cat:2",
}
```

颜色角色的三种写法：

| 写法 | 含义 | 示例 |
|---|---|---|
| 语义色字段名 | 使用主题的语义色 | `"main"`、`"gray"`、`"warn"` |
| `cat:N` | 使用第 N 个分类色（从 0 开始） | `"cat:1"` |
| `#RRGGBB` | 写死色值，不随主题变化 | `"#000000"`（尽量避免） |

新增第 7 个区域后，如果某个主题的 `categorical` 只有 6 个颜色，第 7 个区域会与第 1 个区域同色。这时需要给各主题补充分类色。

## 9. 校验与报错

主题在创建时就会校验，错误会尽早暴露，而不是等到出图时才发现。

| 现象 | 原因 | 处理 |
|---|---|---|
| `ValueError: 主题 'x' 的配置不合法：main` | 颜色不是 `#RRGGBB` 格式 | 改成十六进制写法 |
| `ValueError: ... sequential='xxx'(不是已注册的色图)` | 色图名拼写错误 | 查 matplotlib 色图名，或改用颜色列表 |
| `ValueError: ... 含未知字段：colour` | TOML 中有拼错的字段名 | 对照第 4 节修正 |
| `ValueError: ... fonts 含商业字体 'Microsoft YaHei'` | `fonts` 里写了商业字体 | 换成 4.5 节表中的开源替代品 |
| `ValueError: 主题配置缺少 name` | TOML 中没写 `name` | 补上 |
| `KeyError: 没有名为 'x' 的主题` | 主题名拼错，或 `base` 引用的主题尚未加载 | 检查拼写与文件加载顺序（见 5.1 节） |
| `UserWarning: 主题文件 x.toml 加载失败，已跳过` | 单个 TOML 文件有错误 | 根据告警信息修改；其他主题不受影响 |
| `ValueError: 主题 'x' 已存在` | 代码中重复注册同名主题 | 换个名字，或确认后传入 `overwrite=True` |
| 中文显示为方框；`apply_theme` 打印"⚠️ 本机没有课程用的开源中文字体" | 本机一个思源字体（任何发行名）都没装 | 安装思源字体后重启内核；**不要**改用系统商业字体顶替 |

### 字体名

思源字体的别名会自动展开，一般不需要关心本机装的是哪个发行名。西文字体（如 TeX Gyre 系列）没有别名机制，名字必须和 matplotlib 识别的一致。`apply_theme()` 的返回值就是本机实际生效的字体列表，可以据此确认。查询本机全部可用名字的方法：

```python
from matplotlib import font_manager as fm
sorted({f.name for f in fm.fontManager.ttflist if "CJK" in f.name or "Gyre" in f.name})
```

建议把主题中所有字体安装到团队统一的环境里，再写入 `fonts`。

## 10. 交付前的检查清单

提交新主题前，建议逐项确认：

- [ ] `name` 唯一，且与文件名一致。
- [ ] `categorical` 至少有 6 个颜色，且两两之间能清楚区分。
- [ ] `categorical` 中没有灰色，也没有和 `alert` 相近的红色。
- [ ] `categorical[0]` 等于 `main`。
- [ ] 文字颜色 `ink` / `muted` 在 `background` 上清晰可读；`faint` 只用于来源行这类次要信息。
- [ ] `sequential` 按浅到深排列，`diverging` 中间色接近背景。
- [ ] 色盲友好：用色盲模拟工具（如 Coblis、Chrome 开发者工具的"模拟视觉缺陷"）查看预览图，相邻分类色仍能区分。学术用途尤其需要。
- [ ] 黑白打印可读（学术用途）：转成灰度后，各系列的明暗有差异。
- [ ] `fonts` 中只有开源字体（主题能加载成功即说明没有商业字体）。
- [ ] `apply_theme("主题名")` 的返回值里包含至少一个中文字体，中文没有方框。
- [ ] `sequential` 是主色的单色渐变，不是彩虹色阶。
- [ ] 标题区字号与《图表规范》第 3 节一致，或已登记偏离理由。
- [ ] 运行下面的预览脚本，目视检查折线图、柱状图、热力图三种典型图。

### 预览脚本

把下面的代码保存为 `preview_theme.py`，运行 `python preview_theme.py 主题名`，会在 `image/theme_preview/` 下生成预览图。

```python
import sys
import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from signal_insight import viz, config

name = sys.argv[1] if len(sys.argv) > 1 else config.THEME
rng = np.random.default_rng(3)
hours = np.arange(24)
base = np.exp(-((hours - 14) / 4.5) ** 2)

with viz.use_theme(name) as t:
    fig, axes = plt.subplots(1, 3, figsize=(15, 4.6), layout="constrained")

    # 折线图：检查分类色之间是否容易区分
    ax = axes[0]
    for i, area in enumerate(viz.AREAS):
        y = (base * (1 - 0.12 * i) + rng.normal(0, 0.03, 24)) * (100 - 10 * i)
        ax.plot(hours, y, color=viz.AREA_COLOR[area], label=area)
    ax.set_xlabel("小时")
    ax.set_ylabel("人数（千）")
    ax.legend(fontsize=8, ncol=2)

    # 柱状图：检查语义色、灰色和警示色
    ax = axes[1]
    segs = ["市内来访", "周边居民", "外地来客", "过夜地不明"]
    bars = ax.bar(segs, [42, 27, 19, 12], color=[viz.SEG_COLOR[s] for s in segs])
    bars[2].set_color(t.alert)
    ax.annotate("警示", (2, 19), (2, 30), ha="center", color=t.alert,
                arrowprops=dict(arrowstyle="->", color=t.alert))
    ax.set_ylabel("占比 %")

    # 热力图：检查连续色图（热力图上建议关闭网格）
    ax = axes[2]
    im = ax.imshow(rng.random((7, 24)).cumsum(1), aspect="auto")
    ax.grid(False)
    fig.colorbar(im, ax=ax)

    out = viz.finish(fig, f"主题预览：{name}", t.description,
                     config.SOURCE_NOTE, f"theme_preview/{name}.png")
    print("已保存：", out)
```

## 11. 配色取色建议

- **从品牌规范取色。** 先确定主色，然后在同一色相上调出深、中、浅三档，分别填入 `main_dark`、`main_mid`、`main_light`。
- **分类色要拉开色相。** 相邻颜色的色相间隔尽量大于 40°，明度也要有区别，避免只靠色相区分。
- **从网页或设计稿迁移。** 先找到 CSS 变量与语义的对应关系，再填入字段。下表是 `lively` 主题的迁移对照，可作为参考：

| CSS 变量 | 主题字段 |
|---|---|
| `--visited` / `--choice-bg` | `main` |
| `--tone-primary-stroke` | `main_dark` |
| `--tone-primary-fill` | `main_light` |
| `--accent` | `categorical[1]` |
| `--signal` | `categorical[2]` |
| `--error` | `alert` |
| `--ink` / `--ink-2` / `--ink-3` | `ink` / `muted` / `faint` |
| `--rule` / `--line` | `grid` / `edge` |
| `--stage-bg` | `background` |
| `--stroke-w` | `rc` 中的 `lines.linewidth` |
| `--tone-mint-stroke` | `ok` |
| `--font-ui` | `fonts`（网页里的商业字体如 PingFang SC、Microsoft YaHei 不要照搬，只取其中的开源字体） |

- **学术用途优先考虑现成的色盲友好方案**，如 Okabe-Ito、Paul Tol 系列。连续色图按《图表规范》用主色的单色渐变，并确认转成灰度后明暗单调递增。
